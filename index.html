先看整套系统

以一次故障调查为例。模型决定先查哪个现象，Tool 获取告警，Agent Loop 把结果交回模型，Session 保存调查轨迹。Cordis 负责把这些模块组装在一起，因此可以单独更换模型适配器、工具执行器或会话存储。

模型与运行时

模型提出动作；Harness 准备上下文、执行动作并记录结果。Trajectory 用来回看模型当时接触了哪些证据。

Tool、Skill 与子 Agent

Tool 执行具体操作；Skill 提供一类任务的工作说明；Subagent 接受分派的子任务。MCP 让外部服务也能贡献工具。

预设与组合

标准预设提供通用工具，极简预设缩小能力集合，PTC 预设让程序编排工具。创造类预设可再组合创作工具。Profile 选择整个应用的包，Agent 预设进一步限定单个 Agent 的能力。

第 01 节

运行 DSH，观察第一次工具调用

用一个空数组问题认识模型、工作区和会话。

DeepSeek Harness（DSH）把模型、工具、提示词和执行历史组装成一个能工作的 Agent。模型提出动作，DSH 找到对应的实现、传入参数，并把结果交回模型。要看清分工，只需要一个有明确答案的小项目。

准备一个五分钟能检查完的工作区

以下命令用于新建的练习目录。这里故意留了一个边界错误：README 约定空数组返回 0，函数却会算出 0 / 0。

终端 · 快速体验BASH
node -v                    # 此讲义对应的版本要求 Node.js ≥ 24.9
mkdir -p dsh-lab/workspace/src
cd dsh-lab/workspace
echo '计算平均值；空数组返回 0。' > README.md
cat > src/average.ts <<'TS'
export function average(values: number[]) {
  return values.reduce((sum, n) => sum + n, 0) / values.length
}
TS
npx @deepseek-ai/dsh web

默认地址是 http://127.0.0.1:3080。保持终端运行，在 Web UI 的 Settings → Models 配置模型提供方和凭据，选择上一步的 workspace 目录，再新建一个 Session。凭据在运行机器上配置，现场展示可以在保存后再投屏。

发给 Agent 的任务　“请只读检查 README.md 和 src/average.ts，解释空数组的实际结果，给出最小修复建议。请使用文件读取工具，不运行 Shell，不修改文件。”

怎样知道它真的读过文件？

打开本轮轨迹（Trajectory），找到文件读取的 Tool Call，再展开对应的 Tool Result。看结果里有没有 README 的返回约定，以及函数里的除法。模型给出正确结论，可能只凭经验；一对调用和结果才说明本次检查拿到了哪些证据。

验收　能打开 Web UI、选中模型、选对目录，在同一轮记录里找到两个文件的内容，并解释 average([]) 为什么得到 NaN。建议修复为先检查 values.length === 0，再计算平均值。工作区指定操作目录；实际访问边界由工具权限和运行环境决定。

第 02 节

Cordis 怎样组织插件

用两个插件观察依赖就绪、启动、卸载和清理。

如果告警插件先启动，而 Grafana 客户端还没准备好，谁让它等？如果客户端被替换，谁负责关掉旧插件留下的定时器？Cordis 把依赖声明和资源归属放在同一个插件生命周期里。

概念 在 Grafana 实验中有什么用
Context · ctx Cordis 为插件提供的作用域入口；从这里取服务、监听事件、挂载子插件。
Plugin · apply 可以挂载、运行、卸载的模块。依赖满足后，Cordis 调用入口 apply(ctx)。
Service 供其他插件调用的接口。多个消费者通过 ctx.grafana 共用客户端、连接和缓存。
inject 声明必需服务的名称。提供方尚未就绪，消费者就等待；服务恢复后可重新加载。
Fiber 一次挂载对应的实例，记录状态并持有资源。ctx.plugin(...) 返回 Fiber；await fiber.dispose() 等待清理完成。
Event / effect 事件把变化通知其他插件。ctx.effect 绑定外部资源和释放函数，卸载时一起清理。

  ctx.effect(() => {

如果你用过 NestJS，可以从“调用方依赖接口”理解 Service。NestJS 常见写法从构造器取得 Provider；这里通过 inject 声明依赖、通过 ctx 访问。Cordis 还要在运行中处理服务消失、插件重新加载以及旧资源的清理。

同一个 Grafana 能力，四个概念怎么选？

Plugin 管理安装与生命周期。Service 把能力给同一运行时里的其他代码。Tool 把带参数契约的操作给模型。MCP（Model Context Protocol）让不同应用通过协议发现并使用外部能力。只做一个查询时，可直接写 Tool 插件；多个工具共享鉴权和缓存时再抽 Service；已有可复用的 Grafana MCP Server 时，通过 DSH 的 MCP Client 接入。宿主的会话记录、权限拦截仍由 DSH 管理。

第 03 节

开发一个模型可调用的 Tool

给模型一份它能理解的接口，用只读数据验证整条调用路径。

现在让 Agent 回答“告警 A001 影响哪个服务？”模型只需要知道工具名、用途和输入格式。业务代码、输出校验和结果呈现都留在宿主。下面用两个静态告警替代真实 Grafana，现场演示无需访问生产系统。

把工具注册到 DSH

在源码根目录创建 scratch-plugin/src/my-plugin.ts。这个例子保留结构化返回值，既能渲染给模型阅读，也方便后面的 PTC 程序筛选。

scratch-plugin/src/my-plugin.tsTS
import type { Context } from '@deepseek-ai/cordis'
import { defineTool } from '@deepseek-ai/dsh-tools'

export const inject = ['tools']
const alerts = new Map([
  ['A001', { service: 'order-api', status: 'firing' }],
  ['A002', { service: 'payment-api', status: 'resolved' }],
])

export function apply(ctx: Context) {
  ctx.tools.register(defineTool({
    name: 'get_grafana_alert',
    description: '调查告警时，按 ID 查询影响的服务和当前状态。',
    parameters: {
      alertId: { type: 'string', required: true, description: '例如 A001' },
    },
    output: {
      schema: {
        type: 'object', additionalProperties: false, properties: {
          id: { type: 'string', required: true },
          found: { type: 'boolean', required: true },
          service: { type: 'string', required: true },
          status: { type: 'string', required: true },
        },
      },
      render: (_args, v) => [{ type: 'text', text: v.found
        ? v.id + ' · ' + v.service + ' · ' + v.status
        : '查无告警 ' + v.id }],
    },
    async execute({ alertId }) {
      const id = alertId.trim()
      if (!id) throw new Error('告警 ID 不能为空')
      const row = alerts.get(id)
      return { id, found: !!row, service: row?.service ?? '',
               status: row?.status ?? 'unknown' }
    },
  }))
}

parameters 拦住类型不对的输入。execute 负责业务判断并返回规范值（canonical value）。output.schema 描述这个值的结构；render 把它转换成模型可读的内容。例如程序能取出 found 这个布尔值，人读到的是“查无告警 A999”。敏感字段应在构造规范值时移除，因为程序化调用可能直接读到它们。

第 04 节

配置、打包与组合 Agent

用同一份插件代码组成开发、生产和不同用途的运行环境。

Config 描述这个插件实例怎么运行，Bundle 描述要分发哪些插件与配置，Profile 记录一次应用启动时按什么顺序加载哪些 Bundle。比如 RCA 和 Coding 两套运行环境都可以复用 GitHub 工具包，但只有 RCA 需要查询 Grafana。

给插件加配置契约

下面是一个独立的配置示例。interface Config 供 TypeScript 检查，导出的同名 Schema 供 Cordis 在启动时校验 YAML 并填入默认值。真实请求要把 timeoutMs 传给超时机制，它才会影响网络行为。

config-demo.tsTS
import type { Context } from '@deepseek-ai/cordis'
import Schema from '@deepseek-ai/schemastery'

export interface Config { environment: 'dev' | 'prod'; timeoutMs: number }
export const Config = Schema.object({
  environment: Schema.union(['dev', 'prod']).default('dev'),
  timeoutMs: Schema.number().min(1000).max(60000).default(10000),
})
export function apply(ctx: Context, config: Config) {
  console.log(config.environment, config.timeoutMs)
}

普通参数如超时、环境、结果上限放在 Config；API Token 交给凭据服务或密钥管理系统注入。环境变量负责提供值，Schema 负责判断取值是否合法。

配置叠加时，哪个值会留下？

假设带 Config 的插件在 Bundle 内设了 environment: prod 和 timeoutMs: 5000。Profile 对同一行只写下面的配置。先猜一下最终环境，再展开答案。

- id: configured-grafana

查看最终配置与原因

该行的整个 config 被替换。Schema 随后补入 environment 的默认值 dev，最终是 dev / 30000。若要保留生产环境，应在覆盖行内显式写入 environment: prod。如果缺少无默认值的必填项，加载会失败。

第 05 节

Agent Loop 如何推进一次调查

从一次模型决策追踪到工具执行、会话记录和下一次决策。

用户问“20:00 之后订单服务为什么开始报 500？”模型可以先查指标，再依据查询结果决定是否看日志。DSH 默认的 Agent Loop 负责组装上下文、请求模型、调度工具、记录结果，并在还有工作时继续。调查策略可以写进指令和插件，驱动器可复用同一套执行机制。

Session 保存整段可追问的调查。Turn 对应一轮已领取输入的处理。Step 包含一次模型决策及其工具批次，可能调用零个或多个工具。若首步进入前即被拒，Turn 可以有零个 Step；同一步内也可能重试模型请求。

服务 这次调查中做什么
ctx.agents / ctx.agentLoop 前者创建或恢复 Agent；默认驱动器推进每一轮的步骤。
ctx.systemPrompt / ctx.llm 组装当步指令和可见工具，按模型路由发送请求、处理流式响应。
ctx.tools / ctx.sessions 校验并执行调用，把可重放的事实追加到会话历史。
控制循环 · 教学伪代码，model、runtime 由宿主提供JS
async function investigate(history, model, runtime) {
  for (let step = 0; step < 8; step++) {
    const reply = await model.decide(history)
    history.push(reply.message)
    if (!reply.calls.length) return reply.message
    for (const call of reply.calls) {
      const value = await runtime.execute(call)
      history.push({ role: 'tool', callId: call.id, value })
    }
  }
  throw new Error('达到本次调查的步数预算')
}

真实驱动器还需处理并发、取消、权限、失败和流式交付。当前版本默认同批最多 10 个并发调用，maxParallelToolCalls: 1 可切为串行；独占工具构成执行屏障。取消依赖执行器和工具响应信号。

会话恢复能恢复到哪里？

session/event 提供已接纳的事件。启用 JSONL 持久化后，可以重放日志重建会话，也能查清哪一步拿到了什么结果。若外部系统已完成回滚，而进程在写入 tool/result 前崩溃，重放只能看到“已请求，结果未知”。重试前要按稳定的操作 ID 到外部系统核验；执行方应支持幂等去重。

Native 与 PTC：谁处理中间结果？

Native 把可见工具的接口直接提供给模型；一次响应可同时提出多个调用。PTC（Programmatic Tool Calling）把 run_code 和生成的 TypeScript SDK 提供给模型，程序内部可做循环、条件判断和聚合。底层工具仍受宿主的权限、超时和审计约束。

run_code 程序体 · 配合第三节的结构化 ToolTS
const results = await Promise.all(
  ['A001', 'A002'].map(alertId => tools.get_grafana_alert({ alertId }))
)
inspect(results.filter(r => r.found && r.status === 'firing')
               .map(r => ({ id: r.id, service: r.service })))

两条都查，只有 A001 / order-api 进入摘要。假设十个 ID 已知，逐个请求模型再做一次总结需 11 次模型往返；Native 一次批量发起或 PTC 一段程序都可以只用 2 次。三者都做十次底层查询。PTC 的优势在于处理依赖和压缩中间结果；实际节省的时间和 Token 要按任务测量。

记录发生过什么，或决定能否执行

下面两个模块分别展示事件监听和执行前 Hook。可用第三节的 overlay 方式把文件加入插件树。日志只打印关联元数据；对照会话明细即可配对调用与结果。

loop-logger.ts · 观察已记录的事件TS
import type { Context } from '@deepseek-ai/cordis'
import type {} from '@deepseek-ai/dsh-session'

export const inject = ['sessions']
const tracked = new Set(['turn/start', 'step/start', 'tool/call',
                         'tool/result', 'step/end', 'turn/end'])
export function apply(ctx: Context) {
  ctx.on('session/event', (session, event) => {
    if (tracked.has(event.type)) {
      console.log(session.id, event.seq, event.type)
    }
  })
}
rca-policy.ts · 工具执行前拦截TS
import type { Context } from '@deepseek-ai/cordis'
import type {} from '@deepseek-ai/dsh-tools'

export const inject = ['tools']
export function apply(ctx: Context) {
  ctx.on('tools/pre-execute', async (exec, next) => {
    if (exec.name === 'rollback_deployment') {
      return { kind: 'deny', reason: '本次调查只允许读取证据' }
    }
    return next()
  })
}

next() 把控制权交给后续处理器。命名工具拦截适合演示策略；强制只读还要结合最终守卫 ctx.tools.guard()、工具白名单及外部服务的只读凭据。添加查询能力用 Tool，共享缓存用 Service，观察耗时用事件；当每一阶段都必须由程序严格把关时，可使用 Workflow 或自定义 Agent。

第 06 节

把前五节串成一个 RCA 案例

从一个告警 ID，到一份有证据、可追问的根因调查报告。

原学习路线把 RCA（Root Cause Analysis，根因分析）列为第六步。这里补全一个小型只读案例：让模型拿到告警、指标、日志和部署记录，并把观察事实、候选原因、待验证项分开写。数据全部来自内置样本，适合在投影和离线讲义里演示。

现场演示：相近的告警，证据够不够？

只读告警调查教学样本 · 离线可用
A001 · order-api

三条证据：500 比例上升、等待连接超时、连接池上限调低。待核验连接池占用与同期流量。

把同一份证据接进 DSH

下面的 evidence.js 同时供页面演示和 DSH 插件使用。它只返回能核对的事实。一个样本有连接池变更，另一个样本缺少近期变更和失败日志；面对后者，报告应该保留“原因未定”。

scratch-plugin/src/evidence.js · 两组模拟记录JS
const samples = new Map([
  ['A001', { service: 'order-api', facts: [
    ['M1', '指标', '20:00 后 HTTP 500 比例从 0.2% 升至约 7%。'],
    ['L1', '日志', '失败请求报告等待数据库连接超时。'],
    ['D1', '部署', '19:56 发布，连接池上限从 50 调低至 10。'],
  ] }],
  ['A002', { service: 'payment-api', facts: [
    ['M2', '指标', '支付接口过去五分钟的 P95 延迟从 180 ms 升至 850 ms。'],
  ] }],
])

export function collectEvidence(id) {
  const alertId = id.trim().toUpperCase()
  const row = samples.get(alertId)
  if (!row) return { alertId, found: false, facts: [] }
  return { alertId, found: true, ...row }
}

把 evidence.js 和下面的 rca.ts 放在 scratch-plugin/src/。get_alert_context 提供只读证据，模型负责解释它们，Session 留下这次用了哪份材料的轨迹。

scratch-plugin/src/rca.tsTS
import type { Context } from '@deepseek-ai/cordis'
import { defineTool } from '@deepseek-ai/dsh-tools'
import { collectEvidence } from './evidence.js'

export const inject = ['tools']
export function apply(ctx: Context) {
  ctx.tools.register(defineTool({
    name: 'get_alert_context',
    description: '按告警 ID 读取 RCA 调查所需的指标、日志与部署记录。',
    parameters: { alertId: { type: 'string', required: true } },
    output: {
      schema: { type: 'string' },
      render: (_args, value) => [{ type: 'text', text: value }],
    },
    async execute({ alertId }) {
      return JSON.stringify(collectEvidence(alertId))
    },
  }))
}
scratch-plugin/rca.patch.yml · 替换为本机源码路径YAML
- insert:
    - id: rca-context
      name: '/absolute/path/to/deepseek-harness/scratch-plugin/src/rca.ts'
从源码根目录启动BASH
pnpm dsh web --patch ./scratch-plugin/rca.patch.yml

在新 Session 提问：“请用 get_alert_context 调查 A001。按事实、候选原因、待验证项写三段，给每条事实标注证据编号。”随后在同一会话追问：“如果连接池一直没满，这个假设还成立吗？” 模型应能指出需要核对连接池占用、获取连接延迟和同期流量。

验收　A001 的结论引用真实返回的证据编号；A002 明确写出缺少哪类证据；不存在的 ID 返回 found: false；运行轨迹能找到对应的 tool/call 与 tool/result。页面按钮展示可复现的示范报告，接上真实模型后的措辞会变化。
